**Scope boundary:** only the `backend/cma/` engine, reached via `POST /api/cma/*`, called solely by `src/components/credit-analyst/AdvancedCMAWizard.tsx`. NOTE: there are THREE parallel CMA engines — `cma/` (Credit Analyst, the one we work on), `core/engine`+`api/report.py` (`/api/v1/report/*`), and `main.py` `/master/*`. Do NOT touch the other two.

**Banker-grade engine refinements (commit e4cd156).** After a CA/banker review, tightened 3 treatments to match how a bank recomputes: (1) current ratio & NWC now include CPTL (current portion of term loan = this year's `tl_principal`) in current liabilities — `ratios.py` both functions; (2) inventory_days measured vs COGS not sales; (3) preliminary/pre-op expenditure (preliminary_expenses+registration_license+consultancy_fees+marketing_launch, NOT contingency) amortised over 5 yrs (Sec 35D) — non-cash below-EBITDA charge in `operating_statement.py` (new `prelim_amortisation`/`prelim_written_off` fields), released from `other_assets` in `balance_sheet.py`, added back in DSCR/`cashflow.py`/`fund_flow.py` so tally(=0) & reconcile hold; small DSCR uplift from tax shield. Displayed in report_sections (Form II "Less: Preliminary Expenses Written Off" + DSCR add-back). DELIBERATELY KEPT: constant gross margin across years (margin-expansion assumptions get struck out by banks); unsecured loans as quasi-equity (standard, subject to subordination covenant). Verified: 42 tests pass; all 6 demos still RECOMMEND (DSCR 2.64-4.15, CR 1.86-2.15), tally 0, cashflow reconciles. Principle: correct+conservative = matches the bank's own recompute = fewer objections = approved; do NOT inflate metrics.

**Infinite loading spinner on /credit-analyst (commit dd3ab51).** Page hung forever on the auth spinner. Root cause: `useCreditAnalystAuth` did `onAuthStateChange(async () => await checkAuth())` where `checkAuth` awaited `supabase.auth.getUser()` INSIDE the callback → Supabase holds an auth lock during the callback, `getUser()` waits on the same lock → deadlock → promise never resolves → `authLoading` stuck true → spinner never clears. Intermittent (only when TOKEN_REFRESHED fires on load, e.g. returning after idle). Confirmed Supabase was UP (fast 401 on `/auth/v1/health`) so it was purely the client deadlock, NOT infra. Fix: initial check uses `getSession()` (local, no lock/network) not `getUser()`; `onAuthStateChange` callback is non-async and defers `checkAuth` via `setTimeout(0)`; added 8s watchdog + `cancelled` guard. **Lesson: NEVER `await` another supabase auth call inside an `onAuthStateChange` callback — defer it. Prefer `getSession()` (local) over `getUser()` (network+lock) for gating UI.** Other hooks (useAuth, ProtectedRoute) already use session-only callbacks; only this one had the antipattern.
